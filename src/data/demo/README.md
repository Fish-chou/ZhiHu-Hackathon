# 演示案例说明

本目录放网站首页三个演示按钮用的素材和缓存结果。

## 素材性质

三个演示输入都是**合成测试素材**：参考公开案例的风险机制编写，品牌是虚构的，不指向任何真实企业，也不是客户数据。页面上标注“演示素材，非客户数据”。

| 案例 ID | 按钮名称 | 内容类型 | 设计意图 | 预期结果 |
|---|---|---|---|---|
| `map-store-locator` | 越南敏感地理素材 | 商品详情页（官网门店页） | 复现第三方底图沿用中文岛礁名、App 内嵌同款地图的机制 | 潜在高风险或待人工复核，必须人工复核 |
| `skincare-ad` | 越南语言/文化表达 | 广告文案 | 绝对化用语、竞品比较、医生背书、功效承诺、广告语言版式 | 中风险或待人工复核 |
| `cs-shipping-reply` | 普通安全文案 | 客服话术 | 检验系统不会为了出结果而强行判定风险 | 低风险，显示证据不足 |

v1 只审查文本，所以案例 A 用文字描述了地图图层的标注内容。

## 文件

- `demo-cases.json`：三个案例的输入文本、内容类型、按钮文字。
- `demo-results.json`：缓存结果，由 `scripts/generate-demo-cache.mjs` 调用正在运行的网站 `/api/audit` 生成，不手工编写。每条记录包含：
  - `text`、`contentType`：输入内容；
  - `evidenceIds`：结果引用的全部证据 ID；
  - `response`：接口返回的完整结构化结果（含模型输出经校验后的结果）；
  - `generatedAt`：生成时间；
  - `evidenceSource`：证据来自 Supabase 实时查询还是离线快照；
  - `model`：生成时使用的模型。

## 什么时候显示缓存

- 点击演示按钮时，网站默认实时审查。
- 实时模型、证据库或网络失败，且输入与某个演示案例完全一致时，才显示缓存结果，页面顶部明确标注“演示缓存结果”和生成时间。
- 展示缓存前，服务端会用当前的 verified 证据集合重新核对引用；已不再是 verified 的证据会被移除。

## 重新生成缓存

```bash
npm run build && npm start          # 需要在 .env.local 中配置好 Supabase 和大模型
node scripts/generate-demo-cache.mjs http://localhost:3000
```

脚本只接受两种结果写入缓存：模型实时生成的结果（live），或如实的“未找到可核验依据”（no_evidence）。规则匹配降级结果不会被写成缓存。所有引用的证据 ID 必须在离线 verified 快照中存在，否则不写入。
